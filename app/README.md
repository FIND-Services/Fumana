# Fumana

The talent clearing house for African engineering. Builders prove their worth
through an AI-guided assessment (Zuri); every figure on both portals is
computed in code (Telos), never generated by a model. Employer search is
bias-shielded: no name, photo, or location until an interview is requested.

## Quick start (demo mode)

```bash
npm install
npm run dev
```

No keys needed. The dev server serves the SPA plus two middleware endpoints
(`POST /api/claude`, `POST /api/tts`). Set `DEMO_MODE=true` in `.env` to get
realistic canned LLM responses without a provider key; with no provider
configured the AI surfaces show an explicit inert/waiting state instead of
faking output.

## Going live: Supabase backend

This project is already wired to a Supabase project
(`lvozhbnpvwsvjsdnebsl`). The schema, RLS, masked view, seeds, and both edge
functions (`llm-proxy`, `tts`) are deployed.

The app switches to real persistence and auth the moment two env vars are set
(local `.env`):

```bash
VITE_SUPABASE_URL=https://lvozhbnpvwsvjsdnebsl.supabase.co
VITE_SUPABASE_ANON_KEY=<publishable key, e.g. sb_publishable_...>
```

The publishable/anon key is safe to ship to the browser — RLS enforces
ownership and the bias shield at the database.

Remaining setup (dashboard or CLI):

1. **Function secrets** (never `VITE_`-prefixed) — Dashboard -> Edge
   Functions -> Secrets, or `supabase secrets set --project-ref <ref>`:

   ```bash
   DEMO_MODE=true                        # canned LLM responses, no provider key
   # or go live:
   LLM_PROVIDER=anthropic LLM_API_KEY=<key>
   ELEVENLABS_API_KEY=<key>
   ```

   Until set, the functions return 501 and the app shows its honest inert
   states (SpeechSynthesis fallback for TTS).

2. **Auth providers** — Dashboard -> Authentication -> Providers: email is on;
   add Google, GitHub (builders), Azure/Entra ID (employers).

3. **GitHub Pages deploy** — set repo Variables (`Settings -> Secrets and
   variables -> Actions -> Variables`) `VITE_SUPABASE_URL` and
   `VITE_SUPABASE_ANON_KEY`; the workflow passes them to `vite build`. Unset,
   Pages serves demo mode.

4. **MCP** — `.devin/mcp_config.json` connects the Supabase MCP server to this
   project; run `devin mcp login supabase` to authorize.

To re-apply or evolve the schema: `supabase link --project-ref
lvozhbnpvwsvjsdnebsl` then `supabase db push`. With Supabase unset, every
backend call is a no-op and the app behaves exactly as the in-memory
prototype.

## Scripts

- `npm run dev` — dev server with the local LLM/TTS middleware
- `npm run build` / `npm run preview` — production build / preview
- `npm run lint` — oxlint
- `npm run typecheck` — `tsc` (covers the `.ts/.tsx` files; `App.jsx` is JS)

## Deploy note

The GitHub Pages workflow deploys the static SPA only — `/api/*` does not
exist there. With Supabase configured, model and TTS calls go to the edge
functions, so Pages + Supabase is a complete deployment. Without Supabase,
Pages serves the UI in inert mode.
